# 威胁模型

## 资产

- 用户授权的项目、学习资料、文档、Agent/聊天导出和 GitHub Skills。
- Vault 中的正式知识、`_staging` 提案、`_raw` 证据和 Obsidian 配置。
- Data 中的来源路径、manifest、审计日志、索引状态、备份信息和私有镜像工作区。
- GitHub、Restic 和可选工具的外部凭据；它们不得写入 config 或公共仓库。

## 信任边界

1. 公共 Skill 源码与仓库外私人 Vault/Data 之间。
2. 明确授权根与未授权本机文件系统之间。
3. 确定性生成内容、AI `_staging` 提案与人工正式知识之间。
4. localhost Web 控制台与浏览器之间。
5. 本地数据与 QMD、Restic、GitHub 等外部进程或网络服务之间。
6. 当前已验证 runtime 与待升级 release 之间。

## 主要威胁与控制

| 威胁 | 控制 |
|---|---|
| 过度扫描磁盘或 Home | 逐项绝对路径授权；拒绝文件系统根和 Home 根 |
| 符号链接逃逸 | 拒绝来源根符号链接；遍历时不跟随内容符号链接 |
| 密钥进入页面、日志或公共仓库 | 禁止路径组件、敏感模式脱敏、发布前 privacy audit |
| AI 把会话原文当作知识 | 敏感来源二次授权；结构化提案；`_staging`；逐条人工批准 |
| 生成器覆盖人工笔记 | 仅覆盖带匹配 `generated_by` 标记的页面；否则保护 |
| Web 被局域网或恶意页面调用 | 仅回环监听、Host 校验、CSRF、CSP、body 上限和固定动作白名单 |
| GitHub 意外公开私人知识 | 仓库必须 `PRIVATE`；准备、push 前后都核验；未知即停止 |
| 自动任务静默升级或批准知识 | schedule 仅执行确定性 `update --apply` |
| 软件供应链被替换 | `.skill` 内 wheel 与外部 wheel 同字节；SHA-256、source commit、固定时间戳 |
| 备份不可恢复 | Restic 加密快照、状态记录和独立恢复演练；私有镜像只作次级来源 |

## 明确不防护

- 已被管理员或恶意软件完全控制的操作系统。
- 用户主动授权并批准上传的内容本身存在错误或版权问题。
- 第三方 Obsidian 社区插件读取 Vault；本项目不自动安装插件。
- GitHub、Restic 目标或包索引自身账号被攻破。
- 用户手工修改 Data 内状态文件造成的语义不一致。

## 剩余风险

- Markdown 会保留用户明确授权来源的本机绝对路径；私有镜像中这些路径仍属于隐私信息。
- 文件名和项目摘要可能包含未被模式检测覆盖的敏感语义，需要人工预览。
- Windows ACL 与 Linux mode 语义不同，标准模式只能尽平台能力收紧权限。
- `PRIVATE` 是服务端访问控制，不等于端到端加密；高敏数据仍应依赖 Restic 加密备份而非 GitHub。
- 浏览器 localhost UI 仍依赖本机浏览器安全；检测到未知 Host 或 CSRF 失败时必须拒绝操作。

安全问题请通过仓库的私密安全报告渠道提交，不要在公开 Issue 中粘贴真实路径、token、聊天或 Vault 内容。
